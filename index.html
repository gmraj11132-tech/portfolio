CareerPilot — Smart Placement & Resume Analyzer

An end-to-end full-stack web application designed for B.Tech CSE 7th-semester campus placement preparation. Built with Next.js 16, React 19, TypeScript, Tailwind CSS 4, Prisma ORM, and a Hybrid Multi-Model AI + Deterministic Heuristic Engine.

🚀 Visit Live Deployment
🎯

1. Project Overview & The Real-World Problem

During campus placement drives, over 75% of engineering student resumes are rejected by automated Applicant Tracking Systems (ATS) before any human recruiter or hiring manager reviews them. This happens due to incompatible file formats, poorly parsed column layouts, missing industry keywords, and lack of quantifiable impact metrics.

❌ The Problem for College Students

  • Rejection by ATS due to unparseable formatting or missing keywords.
  • Skill blind spots: Not knowing what skills are missing for a target job description.
  • Unstructured placement preparation: Random questions without tailored technical & HR drilling.

✔️ The CareerPilot Solution

  • Multi-stage PDF/DOCX resume parser with human-in-the-loop verification.
  • 5-category ATS scoring matrix providing concrete, actionable feedback.
  • Job description comparison with instant matching %, missing skills & keyword recommendations.
  • Role-tailored mock interview generator with structured STAR method answer blueprints.
🏗️

2. System Architecture & Working Principle

CareerPilot follows a modern, decoupled layered full-stack architecture built on Next.js 16 App Router, utilizing Server Components for speed, Client Components for reactivity, and secure API Route Handlers for business logic:

+-----------------------------------------------------------------------------------+ | CLIENT LAYER (Next.js 16 + React 19) | | Landing Page • Auth • Dashboard • Upload • Analyze • Jobs • Skills | +------------------------------------------+----------------------------------------+ | HTTPS / JSON / Multipart +------------------------------------------v----------------------------------------+ | SERVER & API GATEWAY LAYER (Edge / Node.js) | | • Session Validation (JWT in HTTP-only Cookie) • Zod Schema Input Validation | | • Rate Limiting & Security Headers (OWASP) • Multi-Stage PDF/DOCX Parser | +---------------------+---------------------------------------+---------------------+ | | +---------------------v-------------------+ +---------------v---------------------+ | HYBRID INTELLIGENCE ENGINE | | PERSISTENCE LAYER | | [Mode A: External Multi-Model LLM API] | | • Prisma 6.19 ORM | | - Gemini 2.0 Flash / GPT-4o / Claude | | • SQLite (Local Development) | | [Mode B: Deterministic Heuristic Core] | | • PostgreSQL (Production Cloud) | | - 100% Offline Rule Engine (Zero Cost) | | • 9 Normalized Relational Tables | +-----------------------------------------+ +-------------------------------------+

🧠 Hybrid AI & Fallback Engine Design (Key Viva Point)

A key engineering innovation in CareerPilot is its Graceful Degradation Architecture. When an API key is provided, the platform queries advanced LLMs for generative recommendations. However, during college lab demonstrations, campus defense, or when API quotas expire, CareerPilot automatically routes to its Deterministic Rule-Based Heuristic Engine. This engine tokenizes text, matches regex taxonomies across 500+ tech skills, and computes weighted scores with zero external latency and zero financial cost.

6. B.Tech 7th Semester Viva / Presentation Quick Reference

Q1: How do you handle non-standard resume layouts?

The parser implements a two-pass token scanner: first locating standard anchor headers, then performing keyword entity matching with a mandatory human-in-the-loop review step before saving.

Q2: What happens if external AI API is down or quota exceeded?

The system gracefully switches to its local Deterministic Heuristic Engine, which computes ATS scores, matching %, and question sets using curated local taxonomies without failing.

Q3: How is user data kept confidential?

Passwords are never stored in plaintext (PBKDF2 SHA-512), JWT sessions are stored in HTTP-only cookies, and all database queries are strictly scoped to the authenticated user ID.

1. Project Overview & The Real-World Cybersecurity Crisis

Globally, over $10.3 Billion is lost annually to social engineering and fraud schemes. Threat actors exploit psychological panic through artificial urgency, bank impersonation, credential harvesting, spoofed domains, and forged payment screenshots. Traditional spam filters and opaque AI chatbots fail users by offering either binary "Is it a scam?" answers with high hallucination rates, or offering no actionable out-of-band verification steps.

❌ The Problem With Existing Solutions

  • Binary verdicts ("Scam" vs "Safe") that provide zero forensic explanation of why.
  • AI Hallucinations: Generic LLMs making definitive claims without citing verbatim evidence.
  • Privacy violations: Services sending user messages and financial screenshots to third-party databases.
  • Lack of offline resilience: If the external AI API is down, the entire analysis fails.

✔️ The ScamShield AI Solution

  • Hybrid Dual-Engine: 70% Gemini 2.5 Flash neural reasoning + 30% deterministic heuristics.
  • Verbatim Flagging: Quotes and annotates the exact deceptive triggers from the user input.
  • In-Browser OCR: Offline Tesseract.js worker extracting text from screenshots without server upload.
  • Actionable Safe Steps: Practical out-of-band verification steps and a strict DO NOT checklist.

6. Technical Defense & Viva Quick Reference

Q1: Why combine Neural AI with a Deterministic Rule Engine?

Pure LLMs can hallucinate false threats or miss known malicious regex signatures. Combining 70% neural reasoning with 30% deterministic heuristics grounds the score in verifiable regex patterns while handling creative social engineering.

Q2: How is user data kept confidential during analysis?

OCR extraction occurs 100% locally in the browser via Tesseract.js Web Workers. In deterministic mode, zero packets leave the user's browser. When Gemini is queried, only the ephemeral prompt is sent without permanent backend logging.

Q3: How does the system avoid false alarms on legitimate bank OTPs?

The signal engine checks for coercive elements. Legitimate bank OTPs state "Do not share this code" (protective intent), whereas phishing messages command "Submit OTP to prevent account suspension within 10 minutes" (coercive intent).
